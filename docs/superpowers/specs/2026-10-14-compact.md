# Compact frontend and public repository

The user approved a compact source backed by the existing checked graph, and supplied smmdsa/PACT for public documentation, examples, roadmap and GitHub Pages. Implement a reversible frontend, not new execution semantics.

Source starts with `pact 0.2`. Module/graph metadata is one named section and one compact JSON value per line. Functions use `fn ID`, metadata lines, `ID = OP OPERANDS`, `return ID`, `end`. Top-level text graph nodes use the same assignment syntax. Fixed opcode schemas define positional operands; aliases get/set/add.wrap retain explicit checked semantics. JSON operands preserve strings and arrays without ambiguous separators. No implicit indices, hidden constants, scope or type inference in this iteration.

Reject duplicate sections, duplicate node IDs, unknown instructions, incorrect operand count, missing metadata, unterminated functions and invalid source. Metadata retains the original closed schemas. Analyze the reconstructed document before serialization and through normal check/build. Preserve optional empty args exactly. Comments may occupy whole lines beginning with #; they do not change semantics and are not retained by canonical serialization. Rationale lives in docs until versioned metadata is designed.

Python 3.10+, Node 20+, no new runtime dependencies. Existing 1 MiB source limit and module safety policy apply to both formats. Test exact reconstruction of both examples, byte-identical Wasm, malformed inputs and CLI builds. Publish English public docs with Spanish context in existing historical docs. Report bytes separately from tokens. Build GitHub Pages documentation and a freshly compiled standalone game. Keep actual Pages activation distinct from workflow preparation.
