# PACT 0.1 — stateful kernel and first platformer

User explicitly requests continuous implementation through a complete first platformer. Proceed without additional approval handoffs. Existing bootstrap remains supported.

New source format: pact.module/0.1.0. Root: format, constants, cells, functions, exports, assets, presentation, tests. i32 is signed 32-bit; arithmetic operations explicitly wrap, signed division traps on zero/overflow. Function nodes have stable IDs, arguments reference IDs within a function, params/locals are named i32 slots. Operators: i32.const, const.load, local.get, local.set, state.load, state.store, numeric/boolean operators, flow.if, flow.sequence, flow.repeat, call. No recursion. Repeat count is literal 0..256. Indexed state access is checked against the declared cell extent at runtime. Immutable cells cannot be stored. Functions declare exact transitive writes; expression operands cannot call mutating functions. Graph nodes are expression recipes evaluated at their use site, not memoized across state changes. State is fixed linear memory, maximum two pages. Guest has no host imports. Host writes declared input cells, calls init/tick, reads rendering cells. Compiler must validate closed records, references, operand types, bounded expansion/loops and state effects before emitting.

Assets: named palettes, glyph-mapped 8x8 tiles, symbolic colors or null transparency. Compiler validates dimensions, palette membership, RGBA colors and references, creates a deterministic RGBA atlas in guest memory. Presentation declares map/entity views and reads cell addresses; browser host only handles keyboard/touch, timing, draw calls, sound and overlays. Gameplay, collisions, enemy decisions, pickup/throw, damage, checkpoints and victory are PACT functions.

Browser delivery: self-contained HTML containing compiled Wasm, manifest, pixel atlas and renderer; no HTTP server, CDN, external images or build dependencies required to play. Source/project archive includes compiler, game source, generator tooling, tests and build instructions. All HTML/browser UI text is Spanish. Original game title: Alien Harvest — an original retro platformer, not a Mario asset reproduction.

Game: one scrolling world, fixed 60 Hz simulation, Q8 subpixel positions, tile collisions, jump with coyote/buffer, climbable ladders, five normal enemies, one boss, reusable throwable vegetables, gems, checkpoint, three lives, invulnerability, victory/defeat/restart. Input arrows/AD, Space jump, X/J pickup/throw, Enter start/restart; touch controls. Presentation uses generated 8x8 tiles with integer scaling and pixel filtering. Camera follows player within world bounds.

Tests: preserve all bootstrap tests; independent Python reference VM vs real Wasm for kernel and deterministic game ticks; malformed source/cycles/recursion/unauthorized writes/asset errors; runtime state-index bounds; movement, collision, jump, pickup ownership, throws, damage cooldown, respawn, checkpoint, boss health, victory and restart. Browser keyboard/touch smoke tests and screenshots; actual browser playthrough to victory via inputs, plus death/restart. Test-only state injection may be used for isolated mechanics and must be labeled; not substituted for a full playthrough.

No claim that responsibility names alone prove semantic cohesion, that unit tests prove arbitrary correctness, or that this game proves agent productivity. Browser execution and CLI use no model or network. Native OS binaries are deferred.

Final constraints: combined evaluation depth <=128; aggregate conservative compiler expansion <=500,000; unit actions have one incoming execution edge. Empty presentation is allowed for non-game modules; nonempty presentation uses the validated platformer host profile. Browser QA was replaced by native Wasm/Canvas plus minimal DOM adapter because the browser executable/managed control plugin was unavailable. CSS and browser/OS compatibility are not claimed verified.
